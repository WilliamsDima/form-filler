# FormFill

Расширение для Chrome/Edge (Manifest V3), которое заполняет веб-формы тестовыми данными из шаблонов.
Работает локально: без серверов, без ИИ, без доступа ко всем сайтам.

## Установка

```bash
npm install
npm run build
```

Затем `chrome://extensions` → включить «Режим разработчика» → «Загрузить распакованное» → папка `.output/chrome-mv3`.

Для разработки с hot reload: `npm run dev` — WXT сам откроет браузер с установленным расширением.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | разработка с hot reload |
| `npm run build` / `npm run zip` | сборка / архив для публикации |
| `npm test` | тесты (Vitest + jsdom) |
| `npm run compile` | проверка типов |
| `npm run lint` | ESLint |
| `npm run icons` | перерисовать иконки в `public/icon` |

## Как пользоваться

1. В попапе напишите значения, по одному на строку. Бейдж слева показывает, как распознана строка.
2. Нажмите «Заполнить форму» (или `Ctrl+Enter` в редакторе).
3. Без попапа: `Alt+Shift+F` или правый клик → «Заполнить форму» → шаблон.

```text
Иванов Иван Иванович          ← разложится по полям «Фамилия», «Имя», «Отчество»
01.08.1990                    ← для <input type="date"> станет 1990-08-01
qa+{{ts}}@example.com         ← новый e-mail при каждом заполнении
Дата выдачи: 01.08.2020       ← метка: в поле с такой подписью
#promo: SALE2026              ← CSS-селектор: точно в это поле
// комментарий
```

Переменные: `{{today}}`, `{{today+30}}`, `{{ts}}`, `{{rand:6}}`, `{{uuid}}`.

## Как это устроено

Заполнение идёт в четыре шага:

1. **Поиск полей** ([src/dom/scanner.ts](src/dom/scanner.ts)): видимые `input`/`textarea`/`select`/`contenteditable`,
   включая открытые Shadow DOM и фреймы.
2. **Классификация полей** ([src/core/fields](src/core/fields)): по словарю признаков в подписи,
   `placeholder`, `name`, `id`, `autocomplete`, `type` и соседнем тексте каждый признак добавляет вес.
   Побеждает тип с наибольшей суммой.
3. **Классификация значений** ([src/core/template](src/core/template)): по формату (регулярки,
   контрольные суммы ИНН и СНИЛС). Составные значения раскладываются на части.
4. **Сопоставление** ([src/core/matching/matcher.ts](src/core/matching/matcher.ts)): каждая пара
   «значение × поле» получает оценку (селектор > метка > тип > по порядку), пары разбираются жадно.
   При равной оценке сохраняется порядок из шаблона.

Запись ([src/dom/writer.ts](src/dom/writer.ts)) идёт через нативный сеттер `value` с событиями
`input`/`change`, как при ручном вводе, поэтому React/Vue/Angular видят изменения.

```
src/
├─ core/            чистая логика без DOM и API браузера, покрыта юнит-тестами
├─ dom/             работа со страницей: поиск, описание и заполнение полей
├─ storage/         шаблоны и настройки (chrome.storage через wxt/storage)
├─ services/        fillTab() — общий для попапа, хоткея и контекстного меню
└─ entrypoints/
   ├─ background.ts  хоткей, контекстное меню, бейдж
   ├─ filler.ts      скрипт, который внедряется в страницу по запросу
   └─ popup/         React UI
```

Постоянного content script нет: `filler.js` внедряется только по действию пользователя через
`activeTab` + `scripting`. Поэтому расширение не запрашивает доступ ко всем сайтам.

Чтобы научить расширение новому типу поля, добавьте правило в
[field-rules.ts](src/core/fields/field-rules.ts) и тест рядом.
